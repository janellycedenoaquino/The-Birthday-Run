## Choices made overnight (nobody awake to ask)
- **`runAction` is deferred to #16 (guards).** It wraps `withRefusals` and maps `GuardError`, both of which live in `src/server/auth/guards.ts`, which doesn't exist yet (#16). Writing it now would mean inventing the guard interface ahead of its feature. #16 adds it to `src/server/errors.ts` (BUILD F-2 now says so).
- **Sentry 11 has no `sendDefaultPii` option.** It isn't in `@sentry/core` 11.1.0's `Options` type (typecheck rejects it; tried). `dataCollection` replaces it. decisions/0012.
- **`dataCollection` also turns off `stackFrameVariables`, `databaseQueryData`, `graphQL`, `genAI` and `queues`.** Sentry 11 defaults them to on; stack-frame locals could hold a password. The scrubber also deletes frame `vars`.
- **`withSentryConfig` is imported from `@sentry/nextjs/config`** (Sentry 11 moved it; the root import broke `next typegen`). Not a build break, so no D1 fallback to 10.75.
- **`logError` sends no user ID to Sentry.** D15 drops `user`; a tag would re-add it by the back door. `userId` goes in the server console line only.
- **`toUserMessage` maps `over_request_rate_limit` → M-5** besides the three §0.3 codes (SPEC §3.4: Supabase's per-IP limits map to M-5). Per-feature masking (M-1–M-3) stays with the features.
- **The scrubber goes slightly past F-4's list** (F-4 updated): also `token=`/`password=` values, key-name redaction (`password|secret|token|cookie|authorization|api_key`), frame `vars`, `transaction` queries, breadcrumb `data` deep-redacted, `request` reduced to `url` + `method`.
- **`global-error.tsx` is created here** (F-4 lists it). It uses Next 16.3's `retry()` (SPEC S-20 said `reset()`; updated). "contact support" is plain text until `appConfig.supportEmail` exists (#9); `error.tsx` stays with F-3 (#10) and must also call `Sentry.captureException`.
- **Sentry build telemetry is off**, source maps are deleted after upload, and the router-transition warning is suppressed (tracing is off).
- **Tunnel finding, not changed:** the generated `/monitoring` rewrite relays to *any* sentry.io project (org/project IDs come from the query), not only our DSN as D24.16 says. Not SSRF (host pinned to `*.sentry.io`). D24.16 is approved, so it wasn't edited: decisions/0012 lays out accept-and-reword vs. a DSN-checking route handler for the user to pick.
